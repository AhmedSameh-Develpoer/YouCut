# YouCut — تصميم حفظ المشروع والتعافي المحلي

الحالة: ملف `.youcut` بإصدار مخطط 1 يسجل فئة المحتوى وإعدادات المحرر الأساسية. فهرس Recent داخل `userData` يحفظ مسار الملف وبيانات عرض احتياطية وآخر وقت فتح، ويرتب حسب آخر فتح/عمل. عند غياب الملف يظل السجل ظاهرًا مع طلب تحديد ملف المشروع؛ زر «فتح مشروع» يقبل `.youcut` ويعيد تسجيله، ويتحقق من معرّف المشروع عند استعادة سجل قديم. ينشأ مجلد `<project-id>.youcut-data` وداخله `downloads` و`cache`. إذا غاب مصدر الفيديو يظل المشروع ظاهرًا ويطلب فتحه إعادة الربط. الحفظ التلقائي يكتب بعد خمس ثوانٍ وعند مغادرة المحرر. مجلد النسخ الاحتياطي قابل للتغيير، ويحفظ آخر نسختين سليمتين، مع استرداد اختياري لنسخة أحدث.

## الهدف

حفظ المشروع في ملف `.youcut` بصيغة JSON، مع مجلد بيانات ملاصق له. يحفظ التطبيق تعديلات المستخدم تلقائيًا، ويتيح استعادة العمل بعد إغلاق مفاجئ، مع بقاء ملفات الفيديو المحلية الأصلية في أماكنها.

## فصل أماكن الحفظ

التصميم يفصل ثلاثة أماكن: ملف `.youcut` الذي يختاره المستخدم عند إنشاء المشروع؛ مجلد `.youcut-data` المجاور للملف، ويضم التنزيلات الخاصة بالمشروع والكاش؛ ومجلد النسخ الاحتياطي الذي يختاره المستخدم من الإعدادات ويحفظ فيه التطبيق نسخ JSON. المنفذ هو ملف `.youcut` وسجل Recent صغير داخل مساحة بيانات التطبيق ومجلد البيانات ومسار نسخ احتياطي قابل للتغيير.

المسار الافتراضي للنسخ الاحتياطي هو `%USERPROFILE%\Documents\YouCut Backups`، ويمكن تغييره من الإعدادات. تحفظ الميزة آخر نسختين سليمتين من JSON دون نسخ الفيديو والكاش. إذا تعذر الوصول للمجلد، يفشل النسخ فقط ويستمر حفظ المشروع الأساسي مع تحذير.

## الملفات المقترحة

لمشروع اسمه `Match Highlights`:

```text
Match Highlights.youcut
Match Highlights.youcut-data/
  downloads/       مصادر جرى تنزيلها من رابط
  cache/           صور مصغرة وملفات Proxy قابلة لإعادة الإنشاء

<مجلد النسخ الاحتياطي الذي يختاره المستخدم>/
  <project-id>/
    recovery/      آخر حالة استرداد ونسختان سليمتان سابقتان
```

**قرار معتمد:** تسمية مجلد البيانات بمعرّف المشروع الثابت، مثل `<project-id>.youcut-data`، بدل اسم المشروع. يظل الربط سليمًا عند تغيير اسم الملف، ويحتوي ملف `.youcut` على المعرّف نفسه. عند نقل المشروع، ينقل المستخدم الملف ومجلد البيانات معًا. إنشاء نسخة مستقلة عبر Save As ينشئ معرّفًا جديدًا لتجنب اختلاط النسخ الاحتياطية.

ملف `.youcut` هو المرجع الدائم لحالة المشروع: معرف ثابت، نسخة مخطط البيانات، أوقات الإنشاء والتعديل، مصدر الفيديو، نطاق التحليل، المقاطع، التوزيع والتتبع، وإعدادات التصدير. التنفيذ الحالي يحفظ الفئة والمصدر وإعدادات القص والكادر والصوت وFPS فقط. لا يوضع محتوى الفيديو الثنائي داخل JSON. ملف محلي يظل مرجعًا لمساره الأصلي؛ مصدر الرابط الذي سينزله التطبيق يُخزن في `downloads`. الملفات المشتقة التي يمكن إعادة بنائها تُحفظ في `cache`.

شكل JSON المقترح، مع حذف التفاصيل غير اللازمة للمثال:

```json
{
  "format": "youcut-project",
  "schemaVersion": 1,
  "projectId": "<stable-id>",
  "name": "Match Highlights",
  "createdAt": "<ISO-8601 timestamp>",
  "modifiedAt": "<ISO-8601 timestamp>",
  "source": {
    "kind": "file",
    "path": "D:/Videos/match.mp4",
    "fingerprint": { "sizeBytes": 123456, "modifiedAt": "<timestamp>" }
  },
  "analysisRange": { "startMs": 0, "endMs": 300000 },
  "clips": [],
  "export": { "container": "mp4", "aspectRatio": "9:16", "maxHeight": 1920 }
}
```

الإحداثيات تكون نسبًا من أبعاد المصدر أو مساحة الناتج، لا بكسلات المعاينة؛ ذلك يحافظ عليها عند تغيير دقة العرض. يجب أن تحتفظ المقاطع بمعرفات ثابتة وأزمنة صحيحة بالميلي ثانية، وتخزن الكاميرا وهدف التتبع والتصحيحات في حقول منفصلة.

سجلات التطبيق العامة تبقى منفصلة عن مجلد المشروع داخل مساحة بيانات YouCut المحلية للمستخدم. لا تحتوي السجلات على الفيديو، وتُنقح المسارات والروابط عند إعداد تقرير تشخيص.

## الحفظ التلقائي

**المنفذ:** ملف المشروع JSON ذو إصدار مخطط، ويضم معرّفًا ثابتًا واسمًا وفئة وتواريخ الإنشاء والتعديل ومسار المصدر وبصمته وإعدادات القص والكادر والصوت وFPS. الفيديو الأصلي لا يُنسخ. الكتابة تمر بملف مؤقت ثم استبدال الملف الرئيسي. حفظ التعديلات المستقرة يبدأ بعد خمس ثوانٍ، ويوجد حفظ متزامن عند مغادرة شاشة المحرر أو إغلاق التطبيق. سجل Recent المحلي يحفظ وقت آخر فتح/عمل ويهاجر صيغة السجل القديمة. ويحتفظ ببيانات عرض المشروع إذا تعذر الوصول لملفه، ويتيح إعادة ربط سجل منقول بعد التحقق من معرّفه. مجلد بيانات ثابت المعرّف مع `downloads` و`cache` ينشأ بجوار المشروع. عند غياب المصدر يتيح الفتح اختيار ملف بديل ويتحقق من قابلية قراءته ومدة القص قبل حفظ المسار الجديد.

**المتبقي:** زر/حالة إعادة المحاولة للحفظ، حفظ نموذج التحليل والمقاطع المتعددة والتتبع والتوزيع، واختبار استرداد كامل من نافذة Windows وعلى أقراص مختلفة.

تُحفظ التعديلات المستقرة تلقائيًا بعد توقف الإدخال لمدة خمس ثوانٍ، وعند الانتقال بعيدًا عن المشروع، وعند طلب إغلاقه. تغيير الوقت الجاري للمعاينة أو تقدم التحليل والتصدير لا يُكتب مع كل تحديث؛ تُحفظ فقط نقاط الحالة المفيدة، حتى لا تتضخم الملفات أو يتباطأ المحرر.

كل حفظ ينشئ JSON كاملًا في ملف مؤقت بجوار `.youcut`، ثم يستبدل الملف الرئيسي ذريًا. النسخ الاحتياطية تُكتب ذريًا في مجلد `<backup>/<project-id>`، وتُحذف النسخ غير الصالحة ويُحتفظ بأحدث نسختين سليمتين حسب وقت تعديل المشروع. النسخة الاحتياطية لا تكرر الفيديو الأصلي أو الكاش.

يمكن اختيار مجلد النسخ الاحتياطي وتغييره من الإعدادات. إذا أصبح غير متاح، يظهر تحذير بعد الحفظ مع بقاء ملف المشروع الأساسي سليمًا. يستطيع المستخدم تغييره من الإعدادات.

## الاستعادة بعد التعطل

عند فتح المشروع، يتحقق التطبيق من الملف الرئيسي ومخطط بياناته. إذا وجد ملف كتابة مؤقتًا كاملًا أحدث أو نسخة احتياطية أحدث، يعرض للمستخدم خيار الاستعادة أو فتح آخر نسخة سليمة. رفض الاسترداد يُسجل لمنع تكرار السؤال عن النسخة نفسها؛ ولا يستبدل التطبيق نسخة سليمة تلقائيًا.

العمليات التي كانت تعمل أثناء التعطل تُعلّم بأنها توقفت بشكل غير متوقع. لا يعاد تشغيل تحليل أو تصدير تلقائيًا؛ يختار المستخدم إعادة المحاولة. ملفات التصدير المؤقتة تظل متاحة خلال إعادة المحاولة وفق سياسة الملفات المؤقتة المعتمدة، وتُحذف بعد النجاح أو الإلغاء النهائي.

## النقل وإعادة الربط

نقل ملف `.youcut` ومجلد `.youcut-data` معًا ينقل بيانات المشروع المملوكة للتطبيق. مجلد النسخ الاحتياطي منفصل ويختاره المستخدم من الإعدادات؛ لا ينتقل تلقائيًا مع ملف المشروع. يظل ملف المصدر المحلي خارج الحزمة لتجنب نسخه؛ إن تغير مساره يطلب التطبيق من المستخدم تحديده مجددًا، ثم يتحقق من الملف قبل إعادة الربط. إذا فُقد مجلد البيانات، يحاول التطبيق فتح ملف المشروع وإعادة بناء الكاش، ويعرض بوضوح أن تنزيلات المصدر أو نقاط الاستعادة غير المتاحة قد تحتاج إلى إعادة إنشاء.

## التوافق والتحقق

يحمل كل ملف `schemaVersion` مستقلًا عن إصدار التطبيق. عند فتح مخطط أقدم، يُجرى ترحيل على نسخة مؤقتة، ثم تحقق، ولا يُستبدل الملف الأصلي إلا بعد نجاح الترحيل والحفظ. الملف غير الصالح يبقى كما هو وتظهر رسالة مع خيار إنشاء تقرير تشخيص.

الحد الأدنى للتحقق قبل اعتماد التنفيذ: حفظ وإغلاق وإعادة فتح دون فقد التعديلات، قتل التطبيق أثناء الحفظ ثم فتح نسخة سليمة أو استردادها، فتح مشروع بعد نقله مع إعادة ربط المصدر، ترحيل نسخة مخطط أقدم، والتأكد من بقاء المصدر الأصلي دون تعديل.

- تنفيذ migration schema والتحقق من ملفات JSON القديمة والتالفة داخل واجهة التطبيق.

تُحفظ إعدادات Face Cam في `editor.faceCam`: تفعيلها، مستطيل المصدر بإحداثيات نسبية، حجمها وموضعها في الناتج الرأسي، وقالب أعلى/أسفل/مخصص. الملفات الأقدم التي لا تحتوي هذا الحقل تُفتح على إعداد معطل افتراضيًا. المنطقة ثابتة يدويًا في هذه المرحلة؛ بيانات التتبع ومفاتيح الحركة غير منفذة.
